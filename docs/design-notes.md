# 화면 디자인 방향

## 목표
목업이 아닌 실제 서비스처럼 보이는 모바일 우선 웹. 친구들과 여행을 마치고 휴대폰 한 손으로 영수증을 올리고, 누가 누구에게 얼마를 보낼지 받아 보는 화면.

서비스 이름은 Travill(트래빌). 이름·소개 문구는 `ui/branding.py` 한 곳에서만 정한다.

## 색
흰 바탕과 진한 본문 위에 강조색은 하나만 쓴다.

| 이름 | hex | 쓰는 곳 | 대비 |
|---|---|---|---|
| 바탕 | `#FFFFFF` | 화면 배경 | |
| 면 | `#F3F4F6` | 입력칸, 송금 메시지, 표 머리줄 | |
| 본문 | `#1B1F26` | 제목·본문 | 흰 바탕 16.5:1 |
| 선 | `#E4E6E9` | 카드·버튼 테두리 | |
| 여권 초록 | `#17654C` | 로고, 주요 버튼, 진행 막대, 받을 돈 | 흰 바탕 7.0:1, 흰 글자 7.0:1 |
| 오류 빨강 | `#C2362B` | 오류 문구만 | 흰 바탕 5.5:1 |

강조색 고르기:
- 토스 파랑(`#0064FF`, `#3182F6` 계열)은 쓰지 않는다. 이 앱은 토스 송금 링크를 보내므로 토스 공식 화면으로 오인되면 안 된다.
- 여행에서 출발했다. 예전 초록 여권의 짙은 초록을 골라 "여행"과 "돈이 들어온다(받을 돈)"를 함께 떠올리게 했다.
- 흔한 기본값 점검: SaaS 파랑·보라, 크림+테라코타, 검정+형광 강조를 피했다. 밝은 청록이 아니라 어둡고 무게 있는 초록이라 흰 글자를 올려도 AA를 넘는다.

## 서체
- Pretendard(OFL) 하나. `static/fonts/PretendardVariable.woff2`를 앱이 직접 내려주고 테마 `fontFaces`로 연결한다. 라이선스 원문은 같은 폴더의 `Pretendard-LICENSE.txt`.
- 크기 위계: 본문 15px, 소제목 17px, 보조 13px 안팎(Streamlit caption). 화면 제목 22px, 시작 화면 로고 40px.
- 굵기: 본문 500, 제목 700, 로고 800.
- 송금 메시지도 같은 서체로 보여 준다. 고정폭 서체는 개발 화면처럼 보여서 쓰지 않는다.

## 레이아웃
- 콘텐츠 최대 너비 480px, 가운데 정렬. 390px 화면에서도 가로 스크롤 없이 좌우 여백 20px.
- 사이드바 없음. 화면 위에 "이전" 버튼과 진행 표시(1/4 설정, 2/4 영수증, 3/4 확인, 4/4 정산).
- 화면마다 주요 버튼 하나를 아래에 고정한다(정산 시작하기, 다음, 정산하기, 정산 파일 저장하기). 나머지는 테두리만 있는 보조 버튼이나 글자 버튼.
- 카드는 그림자 없이 얇은 테두리, 모서리 12px.
- 첫 화면: 로고 자리의 "Travill", 한 줄 소개, "정산 시작하기". 저장한 정산 파일 불러오기는 접힌 보조 영역에 둔다.
- 정산 결과: 사람마다 카드 하나에 "받을 돈"(초록)·"보낼 돈"(본문색)을 크게. 색만으로 구분하지 않도록 글자로도 적는다. 송금 메시지 아래에 늘 보이는 "메시지 복사" 버튼을 둔다(st.code 복사 아이콘은 마우스를 올려야 보여서 휴대폰에서 찾기 어렵다). 복사되는 글 맨 앞에는 `[Travill]` 한 줄이 붙는다.
- 여행 경로 지도: 정산 결과 맨 아래(저장 버튼 위). 결제 순서대로 여권 초록 원에 흰 번호를 단 마커와 같은 색의 움직이는 선(AntPath). 교통비·직접 추가한 결제는 한 장소가 아니거나 주소가 없어 뺀다. 카카오 키가 없으면 지도 대신 안내, 조회가 전부 실패하면 "위치를 불러오지 못했어요", 일부만 못 찾으면 지도 아래에 상호명을 나열한다.

## 문구
- "~해요" 말투, 짧게. 화면 제목은 질문이나 안내 한 문장("누구와 여행했나요?", "이렇게 나누면 돼요").
- `core/`가 만드는 문장(검증 오류, 인식 실패 안내, 송금 메시지 본문)은 이번 작업 범위 밖이라 "~합니다" 말투가 남아 있다.

## 개발 요소 숨김
- `client.toolbarMode = "minimal"`로 Deploy 버튼과 개발자 메뉴를 숨긴다.
- 제목 옆 링크 아이콘은 `anchor=False`, 마크다운은 `anchors=False`로 끈다.
- "인식기: mock" 같은 개발 정보는 보이지 않는다. `RECOGNIZER=mock`일 때만 작은 "체험 모드" 배지를 보인다.

## CSS
테마 설정으로 안 되는 두 가지만 `ui/layout.py`에서 우리가 붙인 key 클래스(`.st-key-page`, `.st-key-page_bottom`)에 적용한다.
- 좌우 여백: Streamlit 기본 1rem(15px)에 5px를 더해 20px.
- 한글 줄바꿈: `word-break: keep-all`로 낱말 중간에서 끊지 않는다.

## 상태·접근성 점검(ui-ux-pro-max 체크리스트)
- 빈 화면: 결제가 없으면 영수증 올리기·직접 추가를 안내한다. 결제가 없을 때는 업로드 화면의 "영수증 읽기"가 주요 버튼이 된다.
- 로딩: 인식 중에는 "영수증을 읽고 있어요 n/전체" 진행 막대.
- 오류: 무엇이 문제인지와 돌아갈 곳(확인 화면으로 돌아가기, 직접 입력)을 함께 둔다. 업로드 제외 안내는 한 상자에 모은다.
- 대비: 본문·버튼·강조·오류 글자 모두 AA(4.5:1) 이상(위 표).
- 키보드 포커스: Streamlit 기본 포커스 링을 유지하고, 복사 버튼에도 `:focus-visible` 테두리를 줬다.
- 좁은 화면: 390px에서 가로 스크롤 없음(scrollWidth 390 확인), 주요 버튼 높이 44px 이상, 2열 입력은 좁은 화면에서 한 열로 쌓인다.
