# AI 활용 기록

## 2026-11-02 단계 1B 구현: 영수증 인식기·일괄 인식·평가 도구

- 내 요청: 구현 계획의 단계 1B(Task 5~10)를 TDD로 순서대로 구현하고 PR을 만든다. 머지는 하지 않는다. Gemini 키가 없으면 실제 API 단계만 건너뛰고 결과를 지어내지 않는다.
- AI가 한 것:
  - 이미지 정규화, 인식기 인터페이스·Mock·Gemini 인식기, 일괄 인식과 결제 건 변환, 평가 지표·실행 스크립트, 샘플 영수증 생성기(13장)를 구현했다. 테스트 81개가 통과한다.
  - 계획에 없거나 계획과 다른 부분 13건을 직접 정했다(Ruling). 예: 이미지가 없는 정답 항목을 오류로 집계, 평가를 30장씩 나눠 실행, 샘플 spec에 `doc_type` 키 추가. 전체 목록은 PR #3 본문에 있다.
  - 새 리뷰어에게 브랜치 전체 검토를 맡겼다. 손상된 이미지 한 장 때문에 일괄 인식 전체가 멈추는 문제를 찾아 테스트를 먼저 쓰고 고쳤다. 사소한 문제 7건은 PR 본문에 후속 작업 후보로 남겼다.
  - `.env`의 `GEMINI_API_KEY`가 비어 있어 모델명 확인과 실제 영수증 1장 스모크 테스트는 하지 않았다.
- 내가 고른 것: 키가 필요한 단계는 보류한다. 머지는 내가 PR을 확인한 뒤 한다. AI가 정한 13건의 승인 여부는 PR 리뷰에서 정한다.
- 이유: 키 없이 실제 API 결과를 지어내지 않기 위해서다.

## 2026-11-02 프롬프트 v1 작성 (`prompts/v1.md`)

- 내 요청: 구현 계획 Task 6에 따라 단순한 첫 버전의 인식 프롬프트를 만든다.
- AI가 한 것: 계획에 적힌 항목만 담아 작성했다.
  - 역할: 한국 영수증·예약 캡처 인식기
  - 필드 설명: `doc_type` 네 종류, 상호, 주소, 일시, 금액, 통화, 분류, 품목, 경고
  - `total_amount`는 할인·포인트를 반영한 실제 결제 금액
  - 카드번호·승인번호·전화번호는 출력하지 않는다
  - 영수증이 아니면 `not_receipt`
  - 날짜는 `YYYY-MM-DDTHH:MM`, 시간이 없으면 `YYYY-MM-DD`
  - 계획에 없던 문장 하나를 더했다: "보이지 않는 값을 추측해서 채우지 않는다."
- 내가 고른 것: 계획대로 단순한 v1으로 시작한다.
- 이유: 단계 3A(Task 16)에서 v1을 측정하고 실패를 분석해 v2와 비교한다. v1은 그 기준선이다. 아직 실제 API로 측정하지 않았다.
